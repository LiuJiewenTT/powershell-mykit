# TT.Git.SplitCommit.ps1 脚本逻辑

> 脚本路径：`bin/TT.Git.SplitCommit.ps1`
> 用户命令：`Split-GitStagedCommit`
> 功能：将 Git 暂存区变更按 UTF-8 字节大小和/或新增行数拆分为多个提交，支持 hunk 级和行级切分

---

## 整体流程

```
暂存区文件列表 → 逐文件计算字节和行数 → 贪心装箱 → 构建提交计划 → 逐批提交
                                                ↓
                                         超限文件按 hunk 切分
                                                ↓
                                         单 hunk 超限按行切分
```

---

## 核心阶段

### 阶段 1：获取暂存区信息

- `__GitSplit_RunGitNameLines "diff --cached --name-only"` 获取暂存区文件列表
- `__GitSplit_GetStagedFileInfo` 保存每个文件的 mode + blob hash（`git ls-files -s`）
- 这些信息在 `git reset` 后恢复暂存区时需要

### 阶段 2：贪心分批

- `__GitSplit_GetFileBytes`：用 `git diff --cached -U0` 提取 `+` 行，计算 UTF-8 字节数
- `__GitSplit_GetFileLines`：同样提取 `+` 行，统计行数
- `__GitSplit_GreedyPack`：同时累加字节和行数，双维度 AND 逻辑判断是否超限
- `__GitSplit_ExceedsLimit`：判断单文件/批次是否超过任意一个上限
- `__GitSplit_FitsInBatch`：判断累加后是否仍在两个上限范围内

### 阶段 3：超限文件切分

- `__GitSplit_ParseHunks`：解析 `git diff --cached -U0` 为 hunk 对象列表，每个 hunk 含 `AddBytes` 和 `AddLines`
- `__GitSplit_SplitFileByHunks`：对超限 hunk（字节或行数任一超限）调用 `SplitSingleHunk` 按行拆分，再双维度贪心分批
- `__GitSplit_SplitSingleHunk`：在单个 hunk 内部按 `+` 行贪心分组，同时检查字节和行数上限

### 阶段 4：实际提交

1. 保存完整 diff 到备份文件（安全网）
2. `git reset` 清空暂存区（不修改工作区）
3. 逐批提交：
   - 整文件批 → `__GitSplit_CommitFiles`：`update-index --add --cacheinfo` + `commit`
   - hunk 切分批 → `__GitSplit_CommitHunks`：累积应用 hunk 到原始 HEAD → `hash-object -w` → `update-index --cacheinfo` → `commit`
4. 失败时用 `stagedInfo` 恢复未提交文件到暂存区

## 关键设计：累积应用模式

hunk 切分提交不采用增量应用，而是**每次从原始 HEAD 累积应用 hunk[0..N]**：

```
提交 1: HEAD + hunk[0]        → blob1 → commit1
提交 2: HEAD + hunk[0..1]     → blob2 → commit2
提交 3: HEAD + hunk[0..2]     → blob3 → commit3
```

**原因**：原始 HEAD 中每行的行尾信息（CRLF/LF）在累积过程中始终可参考，保证行尾格式正确。增量应用会丢失旧行的行尾信息。

---

## 行尾保留策略

`__GitSplit_ApplyHunksToContent` 中的多层保护：

1. **入口逐字节扫描**：拆分行并记录每行行尾类型（CRLF/LF/None）
2. **EolHints（最高优先级）**：从暂存区目标文件解析逐行行尾，附加到子 hunk
3. **pendingEols 队列**：替换型 hunk 删除旧行时，被新行未覆盖的旧行行尾入队，供后续纯插入型 hunk 取用
4. **旧行继承**：替换型 hunk 按顺序继承被替换旧行的行尾
5. **前一行继承**：无以上信息时，纯插入型继承前一行的行尾
6. **BOM 保护**：入口检测 BOM（`EF BB BF`），出口恢复

## 行级切分规则

| hunk 类型 | 切分方式 |
|-----------|----------|
| 修改型（OldCount > 0） | 第一个子 hunk 保留 `-` 行（完成删除），后续子 hunk OldCount=0（纯插入） |
| 新增型（OldStart=0） | 直接按 `+` 行分组 |
| `\ No newline at end of file` | 只附在最后一个子 hunk |

**OldStart 定位策略**（基于旧行号参考系）：
- 第一个子 hunk：`OldStart = 原始 oldStart`
- 后续子 hunk（修改型）：`OldStart = oldStart + oldCount - 1`（旧行最后一行之后）
- 后续子 hunk（新增型）：`OldStart = 0`（旧行不存在）
