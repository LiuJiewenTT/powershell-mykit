# TT.Git.CodeStat.ps1 问题与处理方法

> 脚本路径：`bin/TT.Git.CodeStat.ps1`
> 本脚本逻辑较简单，开发中遇到的问题较少，以下为需注意的设计要点

---

## 问题 1：`+++`/`---` 文件标记行被误统计

**现象**：git diff 输出中的 `+++ b/file.txt` / `--- a/file.txt` 行以 `+`/`-` 开头，会被误当作代码行统计

**处理方法**：过滤时排除三连符号行

```powershell
# 只统计以 +/- 开头，排除 +++ / --- 文件标记
$codeLines = $DiffLines | Where-Object {
    $_ -match '^[+-]' -and $_ -notmatch '^[+-]{3}'
}
```

---

## 问题 2：首次提交无 HEAD^ 导致 diff 失败

**现象**：仓库仅有首次提交时，`git diff HEAD^ HEAD` 报错（HEAD^ 不存在）

**处理方法**：先检测 HEAD^ 是否存在，不存在则切换 `--root` 模式

```powershell
$null = git rev-parse --verify HEAD^ 2>$null
if ($LASTEXITCODE -eq 0) {
    $result = git diff HEAD^ HEAD
} else {
    $result = git diff --root HEAD
}
```

## 问题 3：空 diff 输出导致后续处理异常

**现象**：无变更时 `git diff` 返回 `$null` 或空数组，直接传入 `Compute` 可能出错

**处理方法**：`GetDiff` 中对空结果统一返回 `@()`，`Compute` 入口做空值保护

```powershell
# GetDiff 返回前
if ($null -eq $result -or $result.Count -eq 0) { return @() }

# Compute 入口
if (-not $DiffLines -or $DiffLines.Count -eq 0) {
    return [PSCustomObject]@{ ... }  # 全零对象
}
```

## 问题 4：`-Help` 参数与 `[CmdletBinding()]` 的 `--help` 区别

**现象**：`[CmdletBinding()]` 原生处理 `--help` / `-?`，但自定义的 `-Help` switch 需单独拦截

**处理方法**：用一个 `HelpInterceptor` 函数统一拦截 `-Help`，转发到 `Get-Help -Full`

```powershell
function __GitCodeStat_HelpInterceptor {
    param([string]$CommandName, [switch]$Help)
    if ($Help) {
        Get-Help $CommandName -Full | Out-Host
        return $true
    }
    return $false
}
```

每个方案函数入口处调用：

```powershell
if (__GitCodeStat_HelpInterceptor -CommandName 'Get-GitCodeStat' -Help:$Help) { return }
```

## 问题 5：字符数与字节数的统计口径差异

**现象**：同一份代码，字符数和字节数差异较大（中文等占多字节），用户可能混淆

**处理方法**：
- 方案1（字符数）：`$content.Length`，适合统计字符量
- 方案2（字节数）：`[System.Text.Encoding]::UTF8.GetByteCount($content)`，适合统计存储/传输量
- 文档和帮助中明确标注口径，综合入口同时输出两种结果
