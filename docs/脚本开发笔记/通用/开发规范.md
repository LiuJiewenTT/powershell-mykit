# TT.ToolKit 开发规范

> 适用范围：`powershell-mykit` 项目的所有 PowerShell 脚本（`bin/TT.*.ps1`）
> 核心约束：兼容 PowerShell 5.1，无额外模块依赖，中文系统环境（代码页 936）

---

## 一、脚本结构

### 文件头部

```
<#
.SYNOPSIS
    一句话功能描述
.DESCRIPTION
    详细说明，包含工作流程、参数说明、注意事项、边界处理
.NOTES
    兼容 PowerShell 5.1，无额外模块依赖
.EXAMPLE
    用法示例
#>

[CmdletBinding()]
param( ... )
```

### 函数组织

```
# ============================================================
# 内部辅助函数（以 __脚本前缀_ 开头，下划线表示私有）
# ============================================================

# ============================================================
# 主函数 / 用户命令（公开函数）
# ============================================================

# ============================================================
# 直接运行入口（dot-source 时不触发）
# ============================================================
if ($MyInvocation.InvocationName -ne '.') { ... }
```

### 内部函数命名

- 格式：`__<脚本前缀>_<功能名>`
- 示例：`__GitSplit_RunGitBytes`、`__GitCodeStat_Compute`
- 下划线前缀表示内部私有函数，避免与用户命令冲突

## 二、参数设计

### 基本规则

- 使用 `[CmdletBinding()]` 启用高级参数
- 位置参数用 `[Parameter(Position = N)]`
- 互斥参数显式校验，报错时给出中文提示
- 提供 `-Help` switch，拦截后转发到 `Get-Help -Full`（注意：不使用 `--help`，与 PS 标准参数规范冲突）
- `[CmdletBinding()]` 原生处理 `-?`，自定义 `-Help` 需单独拦截

### 互斥校验示例

```powershell
function __GitCodeStat_ValidateParams {
    param([string]$Commit1, [string]$Commit2, [switch]$Staged)
    if ($Staged -and ($Commit1 -or $Commit2)) {
        Write-Host "错误：-Staged 与 -Commit1/-Commit2 不能同时使用" -ForegroundColor Red
        return $false
    }
    return $true
}
```

## 三、帮助系统

### comment-based help

每个公开函数必须包含完整的 `<# ... #>` 帮助块，包含 `.SYNOPSIS`、`.DESCRIPTION`、`.EXAMPLE`。

### `-Help` 拦截器

```powershell
function __GitSplit_HelpInterceptor {
    param([string]$CommandName, [switch]$Help)
    if ($Help) {
        Get-Help $CommandName -Full | Out-Host
        return $true
    }
    return $false
}
```

### 帮助中暴露用户命令名

脚本级 `-?` 帮助和 comment-based help 中，必须暴露给用户的实际命令名（如 `Split-GitStagedCommit`），而非脚本文件名。

## 四、输出规范

### 展示与取值分离

- **展示用 `Write-Host`**：带颜色、对齐，面向人眼
- **编程取值用 `-PassThru`**：返回原始对象，不输出到控制台
- 避免哈希表/对象直接输出到管道造成"垃圾输出"

### 终端对齐

- CJK 字符按显示宽度计算
- 数字右对齐带千分位：`'{0,12:N0}' -f $value`
- 分区标题用固定格式：`================ [标题] ================`
- 偏好固定/硬编码格式，避免动态宽度计算导致终端抖动

### 颜色约定

| 颜色 | 用途 |
|------|------|
| `Cyan` | 信息性标题、流程说明 |
| `Green` | 成功、完成 |
| `Yellow` | 警告、提示、需注意 |
| `Red` | 错误、失败 |
| `Gray` / `DarkGray` | 次要信息、明细 |
| `Magenta` | 备注、特殊说明 |

## 五、临时文件管理

### 存放位置

- 存放在 `.git/TT.ToolKit/<脚本名>-tmp/`（Git 内部目录，天然被忽略）
- 不依赖项目 `.gitignore`
- 预留子目录命名空间，防止未来脚本分散使用 `.git` 目录

### 命名规则

- 格式：`<功能>-<PID>-<时间戳>-<随机数>.<后缀>`
- 示例：`split-1234-20260817-100200-5678.patch`

### 清理策略

- 正常完成后自动清理临时目录和空的 `TT.ToolKit/` 目录
- 异常退出时保留备份文件，可用于手动恢复
- 启动时清理超过 1 天的残留文件（`CleanStaleTemp`）

## 六、错误处理

### `$LASTEXITCODE` 检查

所有外部命令（git 等）执行后必须检查 `$LASTEXITCODE`，非 0 时报错并返回。

### 失败恢复

- 关键操作前保存备份（如完整 diff）
- 失败时用备份信息恢复状态（如暂存区）
- 破坏性操作（如 `git reset --hard`）前必须先确认

### index.lock 竞态防护

快速连续执行 git 命令时，`update-index` / `commit` 失败需清理 `index.lock` 并重试一次。

```powershell
if ($LASTEXITCODE -ne 0) {
    $cleaned = __GitSplit_CleanIndexLock
    if ($cleaned) {
        Start-Sleep -Milliseconds 200
        # 重试 git 命令...
    }
}
```

## 七、Git 命令执行规范

### 绕过 PS 5.1 管道编码

所有 git 命令输出必须通过 .NET Process 字节流读取，不使用 PS 管道：

```powershell
function __GitSplit_RunGitBytes {
    param([string]$Arguments)
    $psi = New-Object System.Diagnostics.ProcessStartInfo
    $psi.FileName = "git"
    $psi.Arguments = $Arguments
    $psi.UseShellExecute = $false
    $psi.RedirectStandardOutput = $true
    # ... 用 MemoryStream 读取字节，UTF8Encoding 解码
    return ,$bytes  # 逗号前缀防止空数组展平
}
```

### 仓库根目录查找

不使用 `git rev-parse --show-toplevel`（中文路径乱码），改用纯文件系统查找 `.git`：

```powershell
function __GitSplit_FindRepoRoot {
    $dir = (Get-Location).Path
    while (-not [string]::IsNullOrEmpty($dir)) {
        if (Test-Path (Join-Path $dir '.git')) { return $dir }
        $parent = Split-Path $dir -Parent
        if ($parent -eq $dir) { break }
        $dir = $parent
    }
    return ''
}
```
