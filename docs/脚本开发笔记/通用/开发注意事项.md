# TT.ToolKit 开发注意事项

> 适用范围：`powershell-mykit` 项目的所有 PowerShell 脚本
> 以下为 PowerShell 5.1 环境下开发中踩过的坑及应对方法

---

## 一、PowerShell 5.1 语言陷阱

### 1. `$PID` 是只读内置变量

```powershell
# ❌ 报错：无法赋值给只读变量
$PID = $PID

# ✅ 使用其他变量名
$mypid = $PID
```

### 2. 不支持三元运算符 `? :`

```powershell
# ❌ PS 5.1 不支持
$result = $cond ? $a : $b

# ✅ 用 if 语句或子表达式
$result = $(if ($cond) { $a } else { $b })
```

### 3. 不支持 `&&` / `||` 链式命令

```powershell
# ❌ PS 5.1 不支持
git add . && git commit -m "msg"

# ✅ 分步执行 + 检查 $LASTEXITCODE
git add .
if ($LASTEXITCODE -eq 0) { git commit -m "msg" }
```

### 4. `$args` 是自动变量，勿覆盖

```powershell
# ❌ 覆盖自动变量
$args = "diff --cached"

# ✅ 用其他变量名
$cmdArgs = "diff --cached"
```

### 5. 空数组跨函数展平为 `$null`

PS 5.1 函数返回空数组 `@()` 或空 `byte[]` 时，管道会将其展平为 `$null`。

```powershell
# ❌ 调用者收到 $null，无法区分"失败"和"空结果"
return $bytes       # $bytes 长度为 0 时，调用者收到 $null
return @()

# ✅ 逗号前缀防止展平
return ,$bytes
return ,@()
```

**规则**：所有返回数组/字节数组的函数必须加逗号前缀。

## 二、编码与文件 I/O 陷阱

### 1. `>` / `Out-File` 默认 UTF-16 LE

```powershell
# ❌ 默认 UTF-16 LE，git 无法解析
$content | Out-File $tempFile
$diff > $backupFile

# ✅ 字节写入
[System.IO.File]::WriteAllBytes($tempFile, $contentBytes)
```

### 2. PS 5.1 管道按系统代码页解码（代码页 936 / GBK）

```powershell
# ❌ 管道按 CP936 解码 git 的 UTF-8 输出，中文损坏
$lines = git diff --cached --name-only
$lines = $(git diff --cached)

# ✅ .NET Process 字节流 + UTF-8 解码
$bytes = __GitSplit_RunGitBytes -Arguments "diff --cached --name-only"
$content = $utf8NoBom.GetString($bytes)
```

### 3. git 输出中文路径乱码

`git rev-parse --show-toplevel` 在中文路径仓库（如 `新疆业务网关`）下输出乱码，即使通过字节流读取也不可靠。

```powershell
# ❌ git 输出受代码页影响
$root = git rev-parse --show-toplevel

# ✅ 纯文件系统查找 .git 目录
function __GitSplit_FindRepoRoot { ... }
```

## 三、Git 操作陷阱

### 1. `git apply --cached` 不支持 `-U0` 格式

`-U0`（无上下文行）格式的 patch 无法用 `git apply --cached` 应用。

```powershell
# ❌ git apply --cached 对 -U0 支持有限
git apply --cached $patchFile

# ✅ 改用 hash-object + update-index
# 1. 手动应用 hunk 到内容，生成中间状态字节
# 2. git hash-object -w 创建 blob
# 3. git update-index --add --cacheinfo 更新暂存区
```

### 2. `index.lock` 竞态条件

快速连续执行 `git update-index` 和 `git commit` 时，前一个操作可能未完全释放 `index.lock`。

```powershell
# 防护模式：失败时清理 lock 并重试一次
if ($LASTEXITCODE -ne 0) {
    $cleaned = __GitSplit_CleanIndexLock
    if ($cleaned) {
        Start-Sleep -Milliseconds 200
        # 重试...
    }
}
```

### 3. 子目录下 `git diff --cached --name-only` 只返回当前子目录文件

```powershell
# ❌ 子目录运行时只返回子目录的暂存文件
$files = git diff --cached --name-only

# ✅ 先切换到仓库根目录
$repoRoot = __GitSplit_FindRepoRoot
Push-Location $repoRoot
# ... 执行 git 命令 ...
Pop-Location
```

### 4. `git rev-parse --is-inside-work-tree` vs 文件系统查找

`git rev-parse` 输出受编码影响，非 Git 仓库时还可能输出报错信息。纯文件系统查找 `.git` 更可靠。

## 四、文件编码与行尾保护

### 1. BOM 保护

文件操作时入口检测 BOM（`EF BB BF`），出口恢复：

```powershell
$hasBom = ($bytes.Length -ge 3 -and $bytes[0] -eq 0xEF -and $bytes[1] -eq 0xBB -and $bytes[2] -eq 0xBF)
# ... 处理内容 ...
if ($hasBom) {
    # 重新拼接 BOM + 内容字节
}
```

### 2. CRLF / LF 混用行尾

逐字节扫描行尾类型，行操作时行尾与内容绑定：

```powershell
# 逐行记录行尾类型
if ($content[$i] -eq "`r" -and $content[$i+1] -eq "`n") { 'CRLF' }
elseif ($content[$i] -eq "`n") { 'LF' }
```

### 3. 行尾继承优先级

从高到低：
1. **EolHints**：从目标文件解析的逐行行尾（最准确）
2. **pendingEols 队列**：替换型 hunk 删除旧行时留下的行尾
3. **旧行继承**：替换型 hunk 按顺序继承被替换旧行的行尾
4. **前一行继承**：无以上信息时，继承前一行的行尾
5. **默认 LF**：都无信息时，默认 LF

## 五、临时文件陷阱

### 1. 不要使用 `NUL` 作为重定向目标

Windows 下 `nul` 可能被某些 shell 创建为真实文件，用 `$null` 或 `Out-Null` 代替：

```powershell
# ❌ 可能创建名为 nul 的真实文件
git rev-parse ... > nul

# ✅ 使用 Out-Null 或 2>$null
$null = git rev-parse ... 2>$null
```

### 2. 临时文件不放工作区根目录

临时文件存放在 `.git/TT.ToolKit/<脚本>-tmp/`，不依赖 `.gitignore`，不污染工作区。

### 3. `.git` 内部目录命名空间

预留子目录命名空间（如 `TT.ToolKit/split-tmp/`），防止未来多个脚本分散使用 `.git` 目录造成混乱。
